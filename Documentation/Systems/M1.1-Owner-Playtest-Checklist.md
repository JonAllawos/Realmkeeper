# M1.1: owner playtest checklist (release save system and main menu)

Claude has not played the game. These need your hands and eyes. Your own saves stay where they are (`%USERPROFILE%\AppData\LocalLow\DefaultCompany\Realmkeeper\Saves`). Older saves keep loading and appear under "Other saves" in the editor.

**Before you start:** back up that folder if you want to be certain. Nothing in M1.1 deletes or rewrites a save without asking, but it is your data.

## Launch

1. Start the game from the scene. Check the menu reads:
   - Continue, New Game, Load Game, Settings, Credits, Exit Game;
   - then, in the editor only, a "Developer" heading with "New world" and "Campaigns".
2. With no saves in the new slots, Continue should load your most recent older save, because the editor counts as a development build. In a player build with no saves it would be disabled, saying why. Hover over it to read which save it will load.

## New Game

3. **New Game, empty slot.** Choose New Game, then **Start here** on Slot 1. The world "Realmkeeper" begins, and the slot is saved at once. Check the files in the Saves folder: `slot-1.rkworld.json` and `slot-1.jpg`.
4. **New Game, used slot.** Play a little, return to the menu, and choose New Game, then **Replace** on Slot 1.
   - It should ask first, and say the old save becomes the backup.
   - Cancel: nothing changes.
   - Confirm: `slot-1.rkworld.json.bak` now holds the previous game.

## Save Game and Load Game

5. **Pause menu (Esc in a settlement).** **Save Game** opens the slot chooser. Save to Slot 2.
   - The card should show your character, class and level, place, in-game date and time, playtime, the time saved, a picture, and "Ready".
6. **Overwrite.** Save over Slot 2 again: it asks first.
7. **Refused saves.** Start a conversation, or a fight, and try F5 or Save Game. It should refuse, with the reason.
8. **Load Game.** Load Slot 1, then Slot 2. In a game it asks first, because unsaved progress is lost.
9. **Delete** a slot: it asks first, and removes the save, its backup and its picture.

## Autosave

10. **Arrivals.** Travel between a settlement, the country and a place. After each arrival, an `auto-N` file should appear or update. Expect at most one a minute. Watch the Console for "autosave … in N ms" and note the times you see; they are editor timings.
11. **Campaign moments.** Make a campaign decision, or reach a chapter change, in the provisional campaign. An autosave follows, unless one was made in the last minute.
12. **Leaving.** Use Return to Title from the pause menu, and Exit Game. Each makes an autosave first, when allowed.
13. **Rotation.** After four or more autosaves there should still be three `auto-N` files; the oldest is replaced.
14. **Setting.** In Settings, under Game, turn **Autosave** off. Arrivals no longer autosave.

## Continue and recovery

15. **Continue.** Quit, start again and choose Continue. It should load the save you played most recently, which can be an autosave.
16. **A damaged save.** Copy a slot to keep it safe. Then open its `.rkworld.json` in a text editor, change one letter of your character's name, and save the file.
    - Load Game should show the slot as "Damaged (backup available)", or "Damaged" if it has no backup.
    - **Load backup** puts the previous save back and keeps the damaged file as `.damaged`.
17. **An interrupted save.** Leave a file named `slot-3.rkworld.json.tmp` in the folder and start the game. The log says it was removed, and `slot-3` itself is untouched.

## Feel

18. **Hitches.** Each autosave stops the game for roughly half a second at 9 regions. Is the pause at arrivals hidden by the loading screen? Is the pause on leaving acceptable? (M1.2 moves saving off the main thread.)
19. **Sizes.** Check the save screens at your usual resolution and at a small window.
