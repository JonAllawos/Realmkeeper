## 1. What exists (read before changing)

| Area | Finding |
|---|---|
| `TitleScreen` | **Launch menu:** Continue, New world (name and seed), Load world, Campaigns, Settings, Credits, Exit to desktop. **Continue:** loads the newest *file* (by write time) that is Readable and Compatible, with no fallback if the load fails. **Pages:** worlds, new, campaigns, credits. Opened in a game, Continue reads Resume. The screen builds its own `JsonWorldStore` on `persistentDataPath/Saves`. |
| `RealmkeeperBootstrap` | Always starts a world on `Awake` (`EnsureWorld("Realmkeeper", 123456789)` from the scene); the title is an overlay over that running world. The strategic HUD's Save and Load act on the runtime's active slot. |
| `RealmkeeperRuntime` | `ActiveSlot` defaults to `autosave` (a name only, no rotation). `Save(slot)` raises `PreparingSave`, then dispatches `SaveWorldCommand`. `Load(slot)` pauses the clock, loads into the running session and makes the slot active. The save folder is fixed at `persistentDataPath/Saves`. |
| `WorldSessionHost` | `StartNew`, `StartFromSave` and `Shutdown`. Starting while active is refused. |
| `JsonWorldStore` | Atomic write: a temporary file, then `File.Replace` with **no backup path**. On failure the temporary file is deleted. Stale `.tmp` files are not cleaned at start. `ListSaves` reads a 4 KB header by regular expression and sorts by file time. `Delete` removes the main file only. File operations are not behind a seam. |
| `JsonWorldSerializer` | The envelope is `format`, `schemaVersion`, `savedAtUtc` and `world`, indented. Migrations rewrite the JSON tree from v1 upwards, with no checksum. |
| `SaveSlot` | Names are 1–48 letters, digits, `-` or `_`. `autosave` is the default name. |
| Pause menu (`ExplorationController.Phase25.cs`) | Resume; Save (F5), which writes the active slot; Settings; Return to the world map; Main menu (`RkHooks.OpenMainMenu`); Exit to desktop. Leaving asks first. |
| Transitions | `ExplorationController.TravelRoutine` and `ArriveFromMap` show the `LoadingScreen` with `Show`, `Progress` and `Fail`, and close it with `Hide`. |
| Fights and conversations | `WorldData.ActiveEncounter`, `WorldSession.GetRoadFight()` and `WorldData.Conversation`. |
| Playtime | None existed. |
| Commands | `WorldSession.Dispatch`: a working copy, validation, commit, then `WorldChanged(CommandApplied)` after `_dispatching` is cleared. |

## 2. Decisions taken in preflight

1. **Where the checksum is checked.** In the store (the file layer), not in `JsonWorldSerializer.Deserialize`, so serializer-level tests that edit documents keep their meaning. A missing integrity block is accepted, which covers older saves and files rewritten by tools; a present one must match. Store-level tests that hand-edit a current save drop the block, and this is noted wherever it happens.
2. **Developer entries.** "New world" (name and seed), "Campaigns" and "Other saves" stay in the editor and development builds, under a Developer heading. The Phase 19 test path keeps working there.
3. **The pause menu's Save.** It becomes "Save Game", which opens the slot chooser when the title screen is present. Without one (a test scene with no title), it saves the active slot as before.
4. **The test save folder.** Release slot names (`slot-1` and the rest) would collide with the owner's own saves in `persistentDataPath`. `RealmkeeperRuntime.SaveRootOverride` points a test at a temporary folder.
5. **The v27 fixture.** It is written by the pre-M1.1 build (this baseline), before any code change, so the migration test reads a real v27 file.
6. **New Game's world** is "Realmkeeper", seed 123456789: the scene's world, which the game already opens on. It is held in `NewGameDefinition`.
