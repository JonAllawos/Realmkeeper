# M1.1 completion report: release save system and main menu

**Date:** 2026-11-16. **Branch:** `feature/phase-0-1-foundation`. **Brief:** `Briefs/M1.1-Release-Save-System-Brief.md`. **Decision:** ADR-0123.

## Summary

| Area | Delivered |
|---|---|
| Main menu | Continue, New Game, Load Game, Save Game (in a game), Settings, Credits, Exit Game. "New world" (name and seed) and "Campaigns" sit under a Developer heading in the editor and development builds only. |
| Pause menu | **Save Game** opens the slot chooser. **Load Game** is new. Return to Title and Exit Game make an autosave first, when allowed. |
| Slots | `slot-1`…`slot-3` for the player. `auto-1`…`auto-3` rotate: an empty slot first, then the oldest. Older and developer saves are listed in development builds only. |
| Slot cards | A thumbnail; the character, class and level; the place; the in-game date and time; playtime; when it was saved. The state: Ready, Will be updated, Too new for this build, Damaged (backup available), or Damaged. |
| Save format v28 | A one-line summary and a SHA-256 checksum in the envelope, and a `playtimeSeconds` counter in the world. `MigrationV27ToV28` is structural and writes nothing. |
| Reliability | Each overwrite keeps the previous save as `.bak`. A write is read back and compared before it replaces anything. Failed writes leave the save and its backup untouched. Stale `.tmp` files are removed at start-up. A damaged slot offers "Load backup". |
| Continue | Loads the save played most recently (by `playedAtUtc`, not file time). If that fails, it says why and offers the next. It never changes a file. |
| New Game | Asks for a slot and confirms before replacing one. The replaced save becomes the backup. The world is fixed in `NewGameDefinition`: "Realmkeeper", seed 123456789, until M1.3. |
| Autosave | After a completed transition, while the loading screen still shows; after a campaign decision or chapter change; on leaving. Never during a fight, a conversation, a transition or a command, nor within 60 s of any save. A setting turns it off (default on). Each autosave's time is logged. |
| Save rules | Saving is refused during a fight or a conversation, with the reason (`WorldSession.GetSaveBlocker`). A game loaded from an autosave asks for a slot rather than writing into the rotation. |

**Moved to M1.2, as the brief set out:** the 10–15 minute timed autosave, saving off the main thread, and compact JSON.

### A pre-existing, order-dependent test

`Phase19PlayModeTests.TheTitle_FoundsANamedWorld…` fails when run alone or early.
- **Why:** during a PlayMode run the test runner adds its own scene to the build list (index 1, logged), so `TitleScreen.IsLaunchScene` treats it as the launch scene and the title opens on start.
- **Why the baseline passed:** in the full suite an earlier test has already loaded the real scene.
- **Status:** not caused by M1.1, and not fixed here. The M1.1 PlayMode tests close the title in their set-up, so they do not depend on order.

## Measurements

The editor log shows each autosave's time ("autosave (…) in N ms"). The tests used small one-region worlds, so their timings say nothing about a 9-region save. Phase 30 measured about 0.6 s to serialise one in the editor. Writing the backup, the read-back comparison and the thumbnail add to that. **The cost of an autosave at 9 regions was not measured in M1.1**, and nothing was measured in a player build.
